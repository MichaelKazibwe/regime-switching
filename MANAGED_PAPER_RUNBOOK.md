# Managed founder-paper qualification runbook

3 November extension: preparation and dispatch now also require `portfolio_risk_reader` from trusted server configuration, signed `max_daily_notional`, `portfolio_risk_limits` and `portfolio_exposure_limits`, complete fresh account-currency marks, latest completed-session risk history and verified financial/exposure evidence. The provider receives account-bound book/pending/request state; it must use bounded cached inputs rather than perform unbounded network work inside the account write transaction. Required measured caps cover duration, unhedged FX, country, underlying issuer and ADV participation. Pending BUYs cannot be offset by hoped-for SELL fills. Daily notional accounting conservatively counts full open reservations plus observed cumulative fills; reviewed ramp/basket permissions are needed when building a portfolio under relative risk-share limits. No automatic widening of limits is provided. Successful risk reviews are append-only. Cross-currency valuation remains blocked. See [P0_P1_STRENGTHENING_EXECUTION.md](P0_P1_STRENGTHENING_EXECUTION.md).

2 November 2026. The managed source candidate has no executing default entrypoint. `inspect` verifies files and reports no trading/release authority. A successful source check is not broker, image, host or pilot qualification.

1. Stage from a clean reviewed commit with `python3 managed_release.py stage --destination NEW_DIRECTORY`. The explicit `--allow-dirty` option is only for an unqualified review candidate. Private config, `.env`, account databases, broker sessions and runtime reports are excluded from the selected import closure.
2. Verify using `python3 managed_release.py inspect --root NEW_DIRECTORY`. Build only from that directory: `docker build -f Dockerfile.managed-paper -t managed-paper:REVIEW_ID NEW_DIRECTORY`. Never build this Dockerfile against the entire development workspace: COPY uses the minimal staged context. Review CI tests/scans/SBOM/image digest before use.
3. Default container execution verifies the release and exits; it cannot connect or trade. A qualified host/controller must separately configure a protected state directory, non-root ownership, read-only source filesystem, time/disk monitoring, outbound restrictions, secrets, authenticated broker paper access, signed permits, raw quote/instrument readers and current production authorization provider. Do not expose a public API or mount the Docker socket.
4. Discover the IBKR **paper** account read-only with TLS validation. Confirm permitted instruments, currencies, raw quotes, cash/settled cash, positions and open orders. Do not treat a DU prefix or source-code test as broker entitlement. Do not bypass missing corporate-action review or TLS checks.
5. Freeze the account and adopt a one-time signed, reconciled opening position/cash book. Unknown historical costs stay unknown. Initial unsettled cash is blocked pending prior-trade review. Never reseed to hide losses or missing fills.
6. Supply actual `AuthorizedOrderIntent` objects from the existing production risk path. The coordinator requires them by default and rechecks dimensions/fingerprint at dispatch. `simulation_only=True` is for synthetic module exercises and is explicitly denied by the real HTTP paper adapter. Signed limits alone do not replace portfolio risk authorization.
7. Qualify tiny BUY and reduce-only SELL limit orders. Reserve pending sell quantities; never create a short. Exercise partial fills, late fills, rejects, fees, cancel races, disconnections, duplicate callbacks and restart ambiguity. UNKNOWN remains frozen until broker-confirmed signed resolution and fresh reconciliation.
8. Execution events must include cumulative traded notional/fees and broker-reported trade/settlement dates. Journals, quantities and event state update atomically. Available cash excludes unsettled sale proceeds and outstanding buy payables. Confirm actual settlements with account-bound signed evidence; elapsed time alone never settles cash.
9. Reconcile positions, trade-date cash, settled cash, fees and broker open orders after each event. Average carrying cost is not tax-lot accounting. Corporate-action processing, trade busts/corrections, transfer accounting, detailed tax lots and broader product support require separate controlled releases.
10. Verify external alert receipt, restart, backup/isolated restore and exact replay on the actual host. Record each real completed session and completed-month report. Failed connectivity checks and repeated same-session runs do not count as observations. Obtain independent model/security/operations and owner reviews before the founder pilot; client accounts need separate licence/mandate/isolation/country approval.

For initial read-only capture, copy `deploy/managed-paper-capture.example.json` into protected operator configuration, supply the real paper account and trusted CA path, and restrict the file to owner access. Run `python3 managed_probe.py --configuration PROTECTED_CONFIG_PATH`. Private snapshots and hashed receipts go under `var/managed-paper/read-only-captures`; the command prints status only. A successful capture does not authorize orders or count as a performance observation.

Signed order permits must include a nonnegative `fee_buffer`. BUY reservations include that headroom. If an actual fill exceeds the buffer, the true fill and fees are recorded and the account freezes for review; accounting is never discarded to fit the planned budget.

No live broker session, host or alert sender is configured by this runbook. Credentials belong in protected operator configuration, never chat or source control. Current local Gateway/Docker diagnostics are retained separately, not marked qualified.
